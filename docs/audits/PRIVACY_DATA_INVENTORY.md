# Ayinou privacy data inventory

This engineering inventory describes the behavior present in the Phase 6F.7 baseline `a4b45af17a8ad6ace8cd83392db434b8db2ebe59`. A feature's access window, link lifetime, or retry window does not establish a storage retention period. Proposed durations in the master plan still require an operational decision. [Database access and lifecycle](../DATABASE.md) · [Proposed retention and deletion designs](../DATABASE_MASTER_PLAN.md#retention-deletion-auditing-privacy)

## Collection, storage and access

Supabase hosts Auth, PostgreSQL and private Storage for the current environment. Next.js restores Supabase sessions and Fastify applies caller authentication, validation and scoped database access. Browser cookies and local storage carry session or display state as described below. GitHub Actions processes source and synthetic test output. The inventory covers the application and checked migrations. It does not establish provider log, snapshot, backup or email delivery retention.

| Email, password credentials, email confirmation, recovery, TOTP factors and sessions | Supabase Auth collects credentials and factor enrollment. SSR holds session cookies and Fastify receives bearer access tokens. The application references the Auth UUID. | Account holder and authorized Supabase operators through Auth. Ayinou administrator account search omits email and private profile fields. Recent verified TOTP is required for privileged actions. | Password change, TOTP management, and global sign-out are available with the applicable security rules. Revocation is enforced against current sessions. Auth email and logging retention depend on provider settings. Self-service account deletion and export are absent. |

Broad location can contribute to thresholded public aggregate statistics. | Owner-scoped access with the live-session boundary. Public aggregates suppress small and complementary groups. Public names come from the separate display-name field. No required GPS or street address field in the profile. | Members can edit submitted fields. Auth-account deletion can cascade to profile data through existing foreign keys. There is no supported end-to-end deletion or storage reconciliation workflow. |

A badge projection derives from the current verification record and provenance. | Own profile is private by default. Eligible visible and discoverable profiles have bounded public fields. Referral code is shareable and public validation returns a Boolean. Referral attribution and daily activity are private. No hosted blanket retention schedule is installed. |
| Founding Ambassador nominations, consent and recognition | Private candidate and selection records, reasons, notices and participation events. | Platform administrators use the private workflow. A public directory appears only for a currently eligible, independently verified, discoverable participant who consents. | Withdrawal, expiry or revocation removes public recognition. Auth deletion clears the recipient and public statement/consent according to the case lifecycle. Written private reasons remain subject to policy. |
| Project proposals and ownership, reviews, team roles, volunteer records and tasks | Proposal versions, ownership type and reviewer history are private tables. Teams and opportunities add applications, invitations, assignments and activity. | Approved opt-in proposals expose a limited public projection. Draft, reports, applicant notes, staff and assignments require current scoped authority. Reviewer independence and recent TOTP apply where required. | Parent project deletion cascades to linked operations under schema rules. Some retained actor IDs are nulled when an account is deleted. Invitation and access expiry do not erase written records. No self-service retention or export pipeline. |
| Milestones, updates, supporting evidence, metrics and final reports | Versioned project progress rows store workflow events and attachments. Report snapshots record published approved data and its self-reported provenance. | Private evidence stays team-scoped. Approved requested public entries expose a limited projection. A later reviewed correction preserves prior versions. | No routine purge of historical evidence/report revisions. | Polls, choices, nominees, frozen electorates, private ballots and outcomes | PostgreSQL retains scope, status, nominee consent and accepted choices; qualified polls freeze a higher-trust electorate. | Current scope and eligibility control operations. Foreign-key rules can remove actor references from retained records. Written reasons, provider logs, backups and audit holds still require an approved lifecycle. CI retains a counts-only browser artifact for three days. |

## Outstanding data rights and policy decisions

Existing screens offer individual controls such as profile edits, discoverability, membership withdrawal, deletion of eligible posts, recommendation reset, and global session sign-out. They do not assemble a portable data export, start a reviewed account deletion, track a rights request, or verify purge across Auth, database rows, Storage, evidence holds and backups. Some foreign-key rules protect retained records, some detach actor identity, and some delete dependent rows. Issuing an Auth delete alone would not establish completion.

Before collecting public-launch data, decide data ownership and request handling, identity checks for rights requests, export format, deletion sequencing and restoration behavior, category-specific retention, de-identification of ballots and audits, evidence holds and release rules, provider/backup/log retention, and operator access and review. Agree how to record completion and exclusions. Keep public notice, policy drafting and legal assessment separate from this inventory.

The application stores links to independent evidence sources. Production custom SMTP, external identity verification and content scanning are open operational dependencies. The workspaces examined do not implement direct message, radio streaming or payment data collection. Reassess this inventory when any of these integrations changes.
