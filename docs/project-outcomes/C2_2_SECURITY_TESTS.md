# C2.2 Security verification

## Test boundary

Hosted AyiNou is used for read-only verification of catalog privileges, existing records, closed intake and connected application compatibility. Reviewer appointments, assignments, evidence release, changes and findings are exercised on disposable Supabase only.

## Regression evidence

- [Disposable C2.2 browser and API scenarios](../../apps/web/e2e/project-outcome-review.spec.ts) cover current sessions, department and staff lanes, eligibility, expiring authority, evidence release and revocation, revision guards, findings, and challenges.
- [C2.1 scenarios](../../apps/web/e2e/project-outcomes.spec.ts) cover the three native project ownership models, all ten departments, native source binding, privacy and concurrent requests.
- Existing Project Work, project progress, C1 and moderation scenarios exercise the unchanged features around C2.2. Local type, lint, unit, route-contract, shared-contract, localization and production build checks remain part of the phase.

## Hosted rollout guard

Compare the exact tested migration bytes and project identity before application, then verify the remote dry run lists just the authorized migration. Compare original record and authorization fingerprints after application. Verify all C2.2 private tables and service-only RPC authorization, empty review tables and closed gates. Connected browser observations are reported separately from synthetic lifecycle verification.
