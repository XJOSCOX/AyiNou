# A1A pagination and performance

Order is descending by server timestamp, source key and canonical event ID using PostgreSQL byte ordering for the two strings. Each next page uses a strict comparison on the last returned tuple and applies the original high-water timestamp. The cursor is authenticated and encrypted with a key derived from the server's Supabase secret. It is bound to the viewer, verified session, route scope, target, workspace and full filter/limit set. A page sequence has a five-minute lifetime measured from its first cursor. Changing server credentials invalidates existing cursors. No bearer credential or provider session identifier appears in the cursor URL.

The default date range is 30 days; maximum is 90 days per query. Pages cap at 50 and retain one extra item to indicate continuation. Each enabled adapter contributes up to that limit before the global merge. Scope, date, filter and keyset predicates apply in PostgreSQL. Path-scoped and owner-scoped indexes precede time and native ID. Platform account and actor selectors have dedicated scoped indexes. General-feed moderation uses timestamp indexes and verifies the source post's general-feed scope. Search uses fixed projections without user-supplied expressions or materialized event copies. There is a PostgreSQL RPC timeout setting and the existing bounded transport timeout. The shared cross-instance rate counter allows 30 authenticated audit requests per minute and 15 for the anonymous bucket.

Ordinary newer writes after the high-water instant cannot move the cursor or repeat records. Earlier timestamp writes that commit late, retroactively dated events, source deletion/detachment and changing permissions can change later membership. The query does not retain a cross-request PostgreSQL snapshot. Keyset pagination guarantees stable traversal of the eligible rows visible to each page, with those changes reflected at the next authorization check. A1B should restart on a filter change and surface empty or revoked results without inferring private records.

The disposable test loads 50,000 native session events with 2,000 owned by the queried member. It requests two full pages, verifies disjoint event references and checks the shared read limit. The full local regression measured 17 ms and 15 ms through Fastify and disposable Supabase. The test has a three-second two-page budget. [Validation report](A1A_IMPLEMENTATION_REPORT.md)
