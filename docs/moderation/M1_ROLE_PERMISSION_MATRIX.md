## Enforcement and Founder gaps

Founder recognition reads the platform bootstrap and bootstrap audit trail. `platform_access_for_api` exposes the current authority and `private.platform_admin` inherits active, verified-TOTP Admin authority for Founder. `feed_data.moderation_role` explicitly includes Founder. `feed_data.community_review_role` instead combines platform Admin/Founder with scoped staff. Sensitive Feed and event decisions rely on AAL2 plus recent verified TOTP tied to the live session. The web administration surface is a private workspace. The legacy account API checks live role and AAL2 session and takes no workspace ID. Newer workspace-aware APIs such as A1A, Founder direct verification and F2.5 policy writes explicitly bind the request to a private workspace and verify recent step-up. Verification, organization and governance decisions impose their own scope and conflict rules in addition. Global Feed and event moderation already admit Founder. Department/group content decisions inherit through Admin and have separate resource URLs. Founder has an eligible direct representative review route and can assign eligible cases, including a route for independent handling when Founder is conflicted. Founder should be able to reach those routine tools through the private workspace. Confirmed gaps are fragmented navigation and incomplete cross-domain case and history projections, including F2.5 event actions and policy changes. A content action that does not exist, such as independent event appeal or no-report event restriction, is absent for every role. The governance wrapper, own-content conflict and reviewer exclusions are deliberate boundaries. ## Route trace

Account writes route through the admin workspace and `admin_account_action_for_api`. Feed actions route through `/api/v1/moderation/posts/:id` or `comments/:id` and `moderate_scoped_post/comment`. Community actions use `/api/v1/communities/:key/moderation/:target/:id` and `moderate_department_content_for_client`. Event reports use `/api/v1/events/moderation/reports` and `moderate_event_for_client`. Project report decisions use `/api/v1/projects/:id/reports/:report` and `project_report_decide_for_client`. Trust decisions use `/api/v1/trust/*` and separate verification/impersonation RPCs.
