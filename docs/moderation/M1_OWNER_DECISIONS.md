# M1 · Owner decisions before M2

| Decision | Recommended starting point | Owner choice needed |
| --- | --- | --- |
| Sanction durations and defaults | Preserve existing indefinite status. Offer time-bounded suspensions and feature restrictions as explicit new decisions. Reserve indefinite bans for policy-defined high severity. | Allowed durations, limits by moderator role, escalation and exact public terminology. |
| Event decision conflicts | Apply a documented conflict rule aligned with project/trust cases. Allow urgent protective action only under separately approved authority with independent follow-up. | Which organizer, reporter, participant and organization relationships disqualify action, and whether emergency action is permitted. |
| Protected governance and routine Founder access | Reuse current approved routine Founder authority. Keep protected-account cases, special verification, independent review, evidence and ballot privacy behind their existing authorities. | Confirm the desired workspace placement and any new delegated authority requiring separate approval. |
| Moderator and resource scope | Use least-privilege bundles, scoped group/organization permission and a policy-limited maximum duration. Keep policy changes separate from case work. | Which global and scoped actors may act proactively, restore, revoke, appoint reviewers or restrict accounts. |
| Session lifecycle | Treat account access denial and provider session revocation as separate dimensions. Define narrow case access so restricted users can receive decisions or appeal. | When to revoke active and remembered sessions, whether reinstatement needs fresh login, and what identity channel restricted users may use. |
| Existing content and commitments | Preserve data and use explicit visibility or management policies for affected resources. For emergency reassignment use an audited owner recovery process. | Whether existing personally authored materials remain hidden, what happens to open group/organization obligations, and how to handle events, volunteer applications and signed media links. |
| Reports and duplicates | Keep multiple independent reports linked to one case, with case-state disclosure scaled to the viewer. Support proactive decisions with a separately recorded origin. | Which domains gain intake first, category taxonomy, whether resolved resources can be reported again, and reporter visibility. |
| Appeals and restoration | Retain independent review and a 14-day default for newly covered domains only after approval. Preserve each existing lane's rules. Reversal applies to the current decision. | Appealable actions, deadlines, extension rights, restricted-account intake and handling of already-deleted content. |
| Notices and translation | Give a safe summary, effective period, case reference and help/appeal route in all supported locales. Avoid raw report detail. | Channel consent, recipient scope, what to disclose to reporters, and reminders before or at expiry. |
| Evidence and redaction | Use purpose-limited evidence references, access audit and lawful purge/hold. Preserve original statements and mark visible moderation changes. | Per-domain retention windows, appeal holds, who can access originals and when evidence is permanently removed. |
| Implementation priorities | Read-only history/navigation first, then account lifecycle and targeted enforcement, then wider case coverage. | Approve scope and priority for M2 after reviewing M1 findings. |
