# M1 · Feature restriction gaps

No general per-account feature sanction was found. The table identifies existing SQL gates a future targeted restriction would need to cover. A global policy switch, access qualification, visibility filter, block or scoped role is not a per-account feature sanction.

| Capability | Confirmed enforcement today | Proposed enforcement dependency |
| --- | --- | --- |
| Post/draft/publish | Member/onboarding, active author and resource/audience gates. Organization authoring uses eligible role and organization scope. | Check post create, edit/publish transitions and organization acting together. Define draft save and delete exceptions. |
| Comment/reply | Member, readable/interactable parent, block checks and comment/reply parent constraints. | Gate roots and replies, including scoped discussions and alternate direct RPC paths. |
| React/repost/quote | Member, readable/eligible target and checks on existing social projection. Quote is a content write. | Gate each action and keep undo available if approved. Apply resulting visibility consistently across direct and fan-out reads. |
| Follow/mentions | F2.4 identity visibility, active member and pair blocks. Mention resolution and notification visibility recheck the target. | Decide if mention restriction blocks tagged identity resolution or only notification delivery. Preserve unilateral unfollow. |
| Upload media | Member/owner, lease and storage lifecycle, parent attachment access. | Check initialization, finalization, attachment and publish; define what happens to existing uploads and signed links. |
| Create or claim organization | Active member, identity eligibility, organization claims and role checks. Ownership workflow has its own security. | Gate setup, claim and acceptance as separate actions. Preserve approved independent ownership and last-owner constraints. |
| Manage/publish organization content | Active actor plus organization state, effective role, capability/term and content scope. | Determine whether restriction applies to a member across institutions, one member in one institution, or institution-wide publishing. |
| Create/manage event | `f25_event_manage`, policy flags, active actor and organizer or authorized organization scope; save and transitions check command eligibility. | Gate create, edit, publish, announcements and management independently. Preserve safety-critical cancel paths for authorized operators. |
| RSVP to event | `rsvp_event_for_client` rechecks member, event policy/visibility/status and RSVP input. | Gate RSVP registration separately from cancellation/withdrawal and participant-data read access. |
| Create/manage group or community | Member and scoped owner/admin/staff checks, policy and step-up. Group removal can deny joining that group. | Use explicit resource scope and distinguish management, membership and posting. Preserve recovery and owner transfer behavior. |
| Create/submit project | Active member, verified project eligibility, organization authority for organization-backed work and workflow state. | Gate creation, submit, re-submit and publishing/revision. Keep reviewer, team and emergency control independent. |
| Apply to volunteer opportunity | Member and project/opportunity state plus scoped authorization for decisions. | Gate new applications and reapplications while allowing withdrawal and access to existing decisions under policy. |
| Create poll or participate in nominations | Active session/member, poll scope/role, version and eligible nomination response. Ballot casting rechecks electorate and current eligibility. | Separate creation/publication, nomination and voting. Preserve ballot secrecy, existing receipt and correction rules. |

## Coverage and rollout concerns

Use the actual route, underlying RPC and downstream service commands as the unit of coverage. Visibility-only updates can leave writes reachable, while write-only gates can leave stale read projections and notices. Verify public/signed-in availability, owner previews, group and institution roles, alternate actor identities, and state changes during a command. Global F2.5 business switches already have their own revision and Founder policy writer. Preserve the difference between a policy that applies across the platform and a sanction against a specific account or resource.
