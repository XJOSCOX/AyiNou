# Security and privacy

1. Identify actor, live session, scoped resource owner and each permitted command. List anonymous, owner, member, scoped operator, administrator, reviewer and system roles where relevant. Reject cross-account IDs and prevent distinction between missing and inaccessible private objects when appropriate.
2. Enforce live restrictions and current scoped roles on every request and at the data boundary. Privileged actions require the existing recent MFA checks and applicable database assurance. Treat assignment, delegation, conflict of interest and independent review as explicit decisions. Keep equivalent checks on alternate access paths, including direct RPC, background work and storage.
3. Review RLS on tables and views, claims, grants, search paths, object storage policies, standard projections and signed URL access. Test least privilege with both allow and deny cases, including session revocation and assignment changes. Keep raw errors, evidence, account credentials and tokens out of logs and UI.
4. Classify each new value as public, member-scoped, restricted or sensitive evidence. Record why it is necessary, how it is obtained and when consent is required. Minimize identifiers, redact cross-subject values, and design for expiry, export, deletion, inherited ownership and shared records. Keep holds scoped and authorized. Address backups, artifacts and notification projections as well as database rows.
5. Threat-model retries, concurrent writes, stale screens and partially completed external work. Constrain state transitions, check expected versions and authorization close to the write, use scoped unique receipts, and commit required events atomically. Check unauthorized and stale requests cause no effects. Separate security telemetry from private evidence and business audit history.
6. Document response owners, safe evidence collection, containment and alert thresholds before enabling sensitive workflows. For incidents, limit access and duration, preserve scoped evidence, restore service with current consent and grants, and record follow-up and decision history.

Use reviewed releases and runtime gates for legal and privacy operations. Legal approval, acceptance records, data rights, beneficiary processing, health referrals and payments each require a separately approved capability and operating policy. L3 synthetic testing is isolated, and L6 publication requires its existing immutable evidence and availability gates. ## Session and private workflow policy

Remember This Device is opt-in and defaults to unchecked. Ordinary remembered sessions may persist for at most 30 days from the trusted Auth session start. The unchecked policy uses nonpersistent browser credentials and a 12-hour server maximum. Sign-out and revocation remain available in both modes. Browser close alone supplies no reliable server-side evidence.

The trusted Founder and active Platform Administrators have a six-hour absolute maximum regardless of browser preference. Refresh cannot extend it. Administrator activation invalidates earlier sessions for the target account. Current authority checks remove privileges immediately on revocation. Prompt for sign-in and applicable MFA after expiry. Preserve the existing 15-minute TOTP freshness check and action-specific step-up. Founder Verified recipients use ordinary active sessions and an explicit case-bound challenge. MFA is optional for ordinary members. Founders still use recent TOTP and the original private workspace to attest and issue.

Private workflow links use `/s/{flowId}/{step}` with random opaque references. Bind the workflow to a user or authorized participant and, when sensitivity requires it, the initiating session. Check identity, live authorization, expiry, revocation, completion and MFA on each read and write. Ordinary account-owned drafts may resume on another device. Keep credentials, tokens, raw session IDs and OTPs out of URLs. Return nondisclosing errors for unauthorized access.

Activation depends on verified provider support and consistent Next.js, Fastify and PostgreSQL enforcement. [Implementation and tests](../security/SESSION_SECURITY_IMPLEMENTATION_PLAN.md)
