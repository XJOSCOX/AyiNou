# D1 standard member Dashboard implementation report

## Scope

The normal Dashboard is shared by every registered member, including the Founder. It replaces the placeholder with a personal overview, discovery links, official announcements, upcoming Events, public Projects, joined Communities, and conditional C4 Opportunities, C2 Impact and platform statistics. Feed remains separate. Founder configuration lives in Platform Administration → Platform Settings → Dashboard settings. C1–C4 activation rules are unchanged.

## Data model and API

`20261126122000_d1_member_dashboard.sql` adds private versioned settings, owner preferences, translated official announcements, idempotency receipts and a Founder audit ledger. The service-only `d1_dashboard_for_api` RPC returns a bounded self summary. Fastify exposes `GET /api/v1/me/dashboard`, `PATCH /api/v1/me/dashboard/preferences`, and Founder GET/PATCH settings routes. Cards reuse the existing Event, Project, C4 discovery, C2 Impact and privacy-safe homepage statistics projections. Events prioritize the member's going response then start time; Projects use most recent publication time; Opportunities use the existing Latest order. No paid or inferred ranking exists.

## Permissions and audit

The API derives actor and session from the bearer token. PostgreSQL checks the same session and active account for every action. Private counts, memberships, bookmarks and preferences have no cross-account selector. Founder reads and writes require current Founder authority, recent MFA and original-session admin workspace. Settings, announcement publication and withdrawal require a reason, confirmation, expected version and request UUID. A protected mutation commits its audit row and exact retry receipt in the same transaction. Member preference writes commit an actor-scoped receipt and current preference version; ordinary reads do not add audit rows. Disposable tests exercise member denial, invalid workspace, stale versions, retries and withdrawal. See [audit coverage](../standards/AUDIT_COVERAGE_MATRIX.md).

## Privacy and lifecycle

Dashboard responses are private and `no-store`. Only visible saved posts are counted, and member-specific cards use existing visibility projections. Announcement content is platform-authored, supplied in four languages, bounded in size, expires within 90 days and can be withdrawn while retaining the Founder audit trail. Preferences cascade on account deletion; audit history and authored notices are retained under the existing governance retention and hold policy, with forward corrections for removal requests subject to legal holds. Dashboard layout never enables C2–C4 consent or operational gates. Platform statistics use the existing disclosure thresholds. Future C5/C6/C8 cards are absent.

## Localization and accessibility

Dashboard headings, greeting, dates, counts, errors and empty states have Haitian Creole, French, English and Spanish copy. The admin screen has the same four-language controls and requires all four announcement translations. Layout order uses labeled Move up/Move down buttons; visibility uses native checkboxes. Sections use headings and landmarks. The page uses the existing responsive MemberShell, theme tokens and verified badge components.

## Reliability and recovery

Member preference and Founder mutations use version checks, actor locks and idempotent request receipts. Conflicting retries return 409. An unavailable private summary reports that personal totals are temporarily unavailable; the page does not invent zeros. Official announcements are hidden when expired or withdrawn. Additive schema is reversible by a forward correction; preserve settings and audit history when correcting behavior.
