# Ayinou personal data export specification

**DRAFT — NOT APPROVED FOR IMPLEMENTATION OR PUBLICATION**

Proposed read-only export for a verified subject or appropriately scoped authorized agent. The current application has owner views and receipts but no portable export. Design per-field allowlists and scope checks. A legally reviewed request can require a different disclosure scope from a portable package. Avoid treating an export as database access. ## Export inventory and default projections

Source classes are **supplied** (subject input), **derived** (activity, status or system output), **third-party** (another person's data), **security** (secrets or controls), **reviewer** (confidential assessment), and **restricted** (held or legally restricted). The proposed defaults apply only after counsel and domain owners approve the policy. A rights reviewer can escalate contested exclusions without expanding worker grants.

| Domain and sources | Eligible candidates | Restricted or omitted by default |
| --- | --- | --- |
| Auth/account, `public.profiles`, `public.member_private`, `public.user_settings` | Own supplied email and signup metadata where appropriate, username, names, bio, onboarding, visibility, locale, broad residence, account dates/status as approved | Password hashes, credentials, MFA secrets, session or refresh tokens, Auth internals, other accounts and privileged notes |
| Preferences, interests and recommendation state | Supplied settings and interests, own feedback and approved derived categories | Raw ranked lists, snapshot contents identifying unseen private resources, internal scores and other member signals; device-local state is disclosed as outside the server export |
| Member and referral data | Own eligible codes, approved attribution dates or aggregate counts | Referred/referring identities, other people's codes and relationship edges beyond approved projection, anti-fraud signals |
| Feed, groups, communities | Own posts/comments, drafts, supplied text and permitted timestamps, current eligible group participation and role/status | Whole threads, other authors, joined-member lists, staff notes, private replies authored by others, non-current access unless an approved formal access route applies |
| Media | Eligible owned avatar or submitted files within current authorization and approved rights, plus own alt text | Third-party images, object paths, signed URLs, held material and images used in shared private records without separate authorization. If provenance is unknown, reconcile or explicitly exclude |
| Institutions and affiliations | Own role, status, directory consent and applicant-supplied fields where currently eligible | Other members, private organization contacts supplied by someone else, internal invitations, permission audit and disputes except individually reviewed disclosure |
| Trust/verification and appeals | Own application data and reasoned outcome where currently authorized, applicant-supplied public evidence references only if approved | Other applicants, assigned reviewer identities or working notes, private proof files, evidence holds, disputed third-party references, protected impersonation reports |
| Projects and volunteering | Own approved proposal/revision contributions, applications, authored milestones/progress and role/status with current scope | Raw shared projects, other applicants, restricted assignments, confidential review, private team evidence and hidden outcome drafts unless a separately approved projection applies |
| Notifications | Own eligible recipient state, timestamps and generic categories | Sender private details or scoped content that is now unavailable; link thumbnails or sensitive case text |
| Polls | Own eligible participation metadata under approved scope. If permitted, offer only a separately authorized self-service receipt bound to the verified voter and poll | Other voters, frozen membership lists, unredacted nominee/dispute records, voter identities with choices, precise chronology that could reconstruct choices, joins across counts or periods. General export workers, agents by default and reviewers receive no choice data |
| Safety settings, reports and appeals | Own settings, own eligible mute/block choices with identifiers minimized, own submitted report or appeal outcome where safely disclosable | Reporter identities, private profiles of blocked targets, confidential notes, case material on others, moderation telemetry and legally held evidence |

Use the current authorization boundary for linked content at build and when evaluating any exception. The current poll detail RPC binds own receipt to `auth.uid()`, applies poll visibility and emits public/authorized aggregates separately. A future eligible receipt can reuse a voter-bound projection, subject to recent proof, market rules and anti-correlation review. No database tables, voter roster, ballot export for administrators, or arbitrary actor parameter. ## Format, packaging and delivery

Propose a bounded ZIP with UTF-8 machine-readable `manifest.json`, a human-readable `README.txt` or inert accessible HTML, category JSON/JSON Lines and optional bounded reencoded media under relative paths. The manifest includes schema/version, date/time in UTC, scope, case reference, locale, category record counts, checksums, as-of time or per-category cutoff, omitted categories with safe explanations and media descriptions. Use approved stable codes, no active scripts, offsite image fetches or file-system paths. Record supplied vs derived data provenance, ownership and relevant date precision. Version fields and codecs for downstream interoperability. Quote/sanitize filenames and user strings, reject traversal and symlink-like entries, bound per-item and total sizes and handle large cases only through a reviewed partition strategy. A consumer can understand which data could not be included; do not use live database IDs or service tokens as public download identifiers.

Generate from explicit scoped projections at a consistent database snapshot, or record category cutoffs and revalidate latest access before release. Never assume a frozen snapshot authorizes delivery after a revocation, privacy change, source deletion, or new hold. Cancel or regenerate affected packages. Grant the worker only exact case/generation/subject projections over a purpose-bound authorization. Keep secrets and outputs out of application logs, SMTP and administrative UI. Inspect test exports against an adversarial fixture and verify metadata does not reveal suppressed records.

Store artifacts encrypted at rest with authenticated envelope protection and per-artifact keys under approved managed key control; use TLS and private artifact storage separate from user content buckets. Stream within process and size budgets. Avoid plaintext disk, logs, shared caches and client-delivered raw service keys. Recheck a live session, proof freshness, identity, policy, case version and download authorization when retrieving. Prefer an authenticated no-store download proxy so revocation remains enforceable. A download intent is purpose- and session-bound and expires; resume/retry rules must stay within the same authorization window. If short signed delivery is later approved, require a separately reviewed exposure window and revoke the underlying object if the provider supports it. Possession of a URL, receipt reference or mailbox never suffices.

Choose an approved schedule for generation, download intent, artifact expiry and residual provider copies before activation. Revoke a grant immediately on applicable role/session revocation, feature rollback or suspected disclosure. Expiry, cancellation, failed builds and repeated requests must queue verified cleanup of objects, envelopes, fragments and leases, with retries and separate fail states. Treat already downloaded copies separately. A notifier may send a generic “case updated” event with no artifact URL. Audits record which case/actor/operation occurred and counts or checksums only when appropriate. Do not record package contents or choice details.

## Acceptance gates

Exercise cross-account/agent denial, replay/session switch, stale proof, private-group expiry, renderer and ZIP path safety, payload-size refusal, snapshot revocation, suppression and aggregate reconstruction, allowlist completeness, staff denial, media and regulated evidence redaction, hold on build or release, concurrent deletion, link theft, expiration, provider partial failure and eventual cleanup. Verify all four interface locales and accessible manifests. Public claims about availability and scope wait for approved jurisdiction rules, artifact retention, provider/storage proof and privacy review.
