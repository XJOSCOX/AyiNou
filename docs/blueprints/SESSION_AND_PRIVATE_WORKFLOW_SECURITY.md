# Session and private workflow security

| Owner-approved requirement | Effective implementation and open work |
| --- | --- |
| Supabase Auth owns credentials and sessions. Sensitive operations recheck the actor and assurance on the server. | **Implemented.** Next.js SSR cookies/session refresh and protected routes integrate with Auth. Fastify verifies issuer, audience, expiry, subject, AAL and session ID. PostgreSQL `account_session_for_api` checks the live Auth session, account restrictions and applicable AAL2/verified factor. Direct browser RPC and storage use their effective RLS and session predicates. |
| Require recent TOTP for privileged actions. | **Implemented on applicable commands**, including core admin, Founder and F1/O5 commands, with a 15-minute freshness window where used. UI and role flags convey no assurance. Coverage differs by domain; inspect legacy direct SQL and Storage paths before making a universal claim. |
| Remember This Device defaults to unchecked. An ordinary remembered session has a 30-day maximum. An unchecked session has a 12-hour maximum and nonpersistent browser authentication. | **Implemented in S2A.** See the [hosted deployment status](../security/S2A_DEPLOYMENT_AND_TEST_RESULTS.md). Measure both limits from original authenticated session start. Refresh cannot extend them, and browser-close behavior is best-effort. Enforce the deadline on the server. |
| Effective Founder authority and Administrator authority each impose a six-hour absolute maximum regardless of Remember This Device. Recognize the Founder through trusted bootstrap provenance, even without an Administrator assignment. | **Implemented in S2A.** See the [hosted deployment status](../security/S2A_DEPLOYMENT_AND_TEST_RESULTS.md). Enforcement uses the original authenticated session start in Next.js, Fastify and PostgreSQL as applicable. Refresh cannot restart the clock. Preserve the existing 15-minute TOTP freshness requirements on applicable actions. The closed legacy Super Administrator scope gains no capability from this policy. |
| An Administrator promotion cannot carry ordinary remembered-session privilege forward. Administrative authority ends immediately on role revocation. | **Implemented in S2A.** See the [hosted deployment status](../security/S2A_DEPLOYMENT_AND_TEST_RESULTS.md). F1 activation invalidates all earlier sessions for the account. Current role checks continue to deny Administrator actions after revocation. Inventory, device revocation controls and recovery remain open. |
| Show current and other sessions, authoritative times and targeted/all-other revocation. | **Implemented in S2B.** Settings lists only the current account's active sessions and preserves regular Auth logout. Targeted and all-other revocation are enforced by Ayinou. Provider-native targeted revocation and authoritative last activity remain unsupported in this integration. [Sessions](../security/S2B_ACTIVE_SESSION_MANAGEMENT.md) |
| Use opaque private workflow references and check every operation. | **Implemented for two S2B workflows.** Organization drafts are account-bound. Leadership sign-out confirmation is bound to the exact initiating session and recent verified MFA. F1/F1.1 continue using their dedicated paths. [Private router](../security/S2B_PRIVATE_WORKFLOW_ROUTER.md) |

Themes, ordinary settings, F1 bootstrap and F1.1 activation continue through their existing paths. [Workspace authorization](../security/S2C_WORKSPACE_AUTHORIZATION.md)

## Reference and binding rules

| Workflow | Current binding or proposed policy |
| --- | --- |
| Public profiles and authorized domain links | A valid UUID/slug or route only locates a record. Server and SQL enforce current authorization, including when the account or organization context switches. A public identifier can be public without exposing private details. |
| O2 organization draft | Account-bound, cross-device resume for the same eligible user. Reconcile delayed writes by actor/version/receipt. Role loss, revocation and a different account close access. |
| F1 `/setup/f/{id}` | Before signup, secret-first authorization binds to the browser through the restricted cookie. Final claim binds the configured mailbox, staged account and its live MFA-backed session. The cookie is not an Auth session ID. |
| F1 `/activate/a/{id}` | Exact target account, authorized proposal, hashed code and live recent MFA. Legacy F1 requires a separate O5 approver. F1.1 recognizes the recorded direct Founder decision for new reserved appointments. Both retain target acceptance. F1 does not pin redemption to the initiating Founder’s session or to one target device. |
| S2B `/s/{flowId}/{step}` | Server-owned state records kind, owner, scope, one permitted step, version, expiry and cancellation. Organization drafts allow their eligible owner on a different session. Leadership confirmation requires the original session. Expiry requires a new link from the original screen. |

Never put bearer material, passwords, OTPs, raw session IDs or verification secrets in query strings, paths, referrers or logs. Code entry is separate from delivery of the opaque locator. Use no-store on private responses, generic denials, scoped allowlisted redirects and transactional completion. Test copied URL, account switch, second device, revoked sessions, expiry, refresh concurrency and authorization drift. Provider support, retention, rollout and incident operations require separate evidence and approval.
