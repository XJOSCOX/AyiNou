# Session and private workflow security

| Owner-approved requirement | Effective implementation and open work |
| --- | --- |
| Supabase Auth owns credentials and sessions. Sensitive operations recheck the actor and assurance on the server. | **Implemented.** Next.js SSR cookies/session refresh and protected routes integrate with Auth. Fastify verifies issuer, audience, expiry, subject, AAL and session ID. PostgreSQL `account_session_for_api` checks the live Auth session, account restrictions and applicable AAL2/verified factor. Direct browser RPC and storage use their effective RLS and session predicates. |
| Require recent TOTP for privileged actions. | **Implemented on applicable commands**, including core admin, Founder and F1/O5 commands, with a 15-minute freshness window where used. UI and role flags convey no assurance. Coverage differs by domain; inspect legacy direct SQL and Storage paths before making a universal claim. |
| Remember This Device defaults to unchecked. An ordinary remembered session has a 30-day maximum. An unchecked session has a 12-hour maximum and nonpersistent browser authentication. | **OWNER APPROVED — NOT YET IMPLEMENTED**. Measure both limits from original authenticated session start. Refresh cannot extend them, and browser-close behavior is best-effort. Enforce the deadline on the server. |
| Effective Founder authority and Administrator authority each impose a six-hour absolute maximum regardless of Remember This Device. Recognize the Founder through trusted bootstrap provenance, even without an Administrator assignment. | **OWNER APPROVED — NOT YET IMPLEMENTED**. Enforce from original authenticated session start in Next.js, Fastify and PostgreSQL as applicable. Refresh cannot restart the clock. Preserve the existing 15-minute TOTP freshness requirements on applicable actions. The closed legacy Super Administrator scope gains no capability from this policy. |
| An Administrator promotion cannot carry ordinary remembered-session privilege forward. Administrative authority ends immediately on role revocation. | **OWNER APPROVED — NOT YET IMPLEMENTED** for promotion-time session enforcement. Revoke or constrain prior ordinary sessions before granting privileged access, retain existing live role checks, and verify revocation across devices. Legacy-session migration, provider capabilities and recovery remain open. |
| Show current and other sessions, authoritative times and targeted/all-other revocation. | **Not implemented** as an integrated console. Existing login, logout, recovery and MFA remain supported. Provider capabilities for stable IDs, original creation, last activity and revocation need operational evidence. Defer unsupported timestamps instead of fabricating them. |
| Use opaque private workflow references and check every operation. | **Partly implemented.** F1 uses dedicated paths with live checks; O2 drafts already use subject-owned resume. A shared `/s/{flowId}/{step}` router, durable workflow policy, session binding and migration of legacy links are **not implemented**. Preserve current flows while specifying compatibility. |

## Reference and binding rules

| Workflow | Current binding or proposed policy |
| --- | --- |
| Public profiles and authorized domain links | A valid UUID/slug or route only locates a record. Server and SQL enforce current authorization, including when the account or organization context switches. A public identifier can be public without exposing private details. |
| O2 organization draft | Account-bound, cross-device resume for the same eligible user. Reconcile delayed writes by actor/version/receipt. Role loss, revocation and a different account close access. |
| F1 `/setup/f/{id}` | Before signup, secret-first authorization binds to the browser through the restricted cookie. Final claim binds the configured mailbox, staged account and its live MFA-backed session. The cookie is not an Auth session ID. |
| F1 `/activate/a/{id}` | Exact target account, approved proposal, hashed code and live recent MFA. F1 does not pin redemption to the initiating Founder’s session or to one target device. Other target sessions are evaluated under current rules. |
| Future `/s/{flowId}/{step}` | Server-owned state includes flow kind, owner, allowed participants/steps, role/resource scope, version, expiry, revocation and any required protected initiating-session reference. Account-bind ordinary drafts. Select initiating-session binding for high-risk flows after a threat review. Define safe reentry when that session expires. |

Never put bearer material, passwords, OTPs, raw session IDs or verification secrets in query strings, paths, referrers or logs. Code entry is separate from delivery of the opaque locator. Use no-store on private responses, generic denials, scoped allowlisted redirects and transactional completion. Test copied URL, account switch, second device, revoked sessions, expiry, refresh concurrency and authorization drift. Provider support, retention, rollout and incident operations require separate evidence and approval.
