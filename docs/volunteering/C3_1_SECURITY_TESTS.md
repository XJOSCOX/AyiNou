# C3.1 Authorization and security checks

The route layer derives actor, session and recent authentication from the existing verifier. Read budgets, strict request bodies, version checks, bounded arrays and text, and no-store/no-index headers apply. PostgreSQL rechecks the account session and allows no role to read tables directly. Only the backend service role can execute the RPC. Founder commands also recheck recognized authority and the original private administrative workspace. The catalog lock serializes term reservations and retirement against profile writes. The session lock serializes profile revisions. Protected catalog/configuration changes commit immutable snapshots and receipts with their mutations. Owner writes commit current preferences, distinct consent, and the most recent receipt together.

The disposable browser test covers the closed gate and owner save flow, both member categories, alias search, validation, two concurrent revisions, expiry, withdrawal, pause, permission grants, the protected Founder command, and four translated narrow/desktop views. The connected browser tests are read-only. Their results belong in the implementation report. No hosted account or case mutation is needed to validate the new roles.

Future projections must independently combine purpose-specific consent, current availability, membership and project scope, native privacy, active account status, blocking on both sides, and safeguarding rules. This version only projects the owner's private record to that owner. There is no organizer, administrator, or member-reader route for another account.
