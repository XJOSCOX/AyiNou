## Independent recovery inventory

Record provider configuration version, approved HTTPS Site URL/callback allowlist, email confirmation and recovery templates, OTP settings and rate limits, SMTP configuration references, password rules, TOTP settings, OAuth providers, current signing scheme and key references, integration and webhook settings, and Storage bucket policy/configuration references. Keep the inventory access-controlled. Auth database rows never substitute for these managed settings.

Restrict vault and key access. Record key ownership, creation status, expiry, rotation and revocation runbooks without raw values. Reconnect OAuth, SMTP, application credentials and integrations from their authorized vault by references. Reconcile cases where a provider restore copies encrypted database material, but use isolated secrets and disable outbound hooks while testing. Inventory scheduled jobs, database webhooks and external-capable extensions before authorizing a provider clone. If they cannot be contained immediately, use the reviewed logical path. Validate live roles, revocation state, JWT acceptance, MFA and restored-session invalidation before the independent verifier clears traffic. The planned S2 session policy remains a separate milestone.
