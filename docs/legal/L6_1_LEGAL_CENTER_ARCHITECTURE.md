# L6.1 Legal Center architecture

The public routes are `/legal`, `/terms`, `/privacy`, `/community-guidelines`, `/legal/organizations`, `/legal/projects-and-volunteers`, `/legal/voting`, `/legal/verification`, `/legal/cookies`, `/legal/data-rights`, and `/legal/history`. They use the public site shell and require no account. Unknown policy IDs and unknown requested versions return 404. The initial release and evidence JSON registries are empty, so all known routes show a short unavailable state with `noindex` metadata. No document has an effective date on the site.

`apps/web/src/lib/legal/publication.ts` defines the immutable release shape and a read-only registry builder. Published content is a structured document with stable section IDs and restricted block types. It is rendered as escaped React text, with links limited to root-relative paths or HTTPS. No raw Markdown loader, arbitrary path endpoint, database write, or publication UI exists. Legal drafts stay under `docs/legal` and are not imported by web runtime code or copied to `public`.

A release is identified by policy ID and semantic version. It records source version and digest, operator, jurisdiction, approved effective date, actual publication timestamp, review evidence references, publication authority, optional superseded version, and four locale variants. Each variant has a document digest, translation digest, human linguistic review and jurisdiction review references. Registry construction validates the package against separately supplied trusted evidence and frozen source records. Historical versions cannot be overwritten; a new version must name its predecessor. Only published releases appear in history. The JSON registry is committed as an immutable artifact; changes require a reviewed deployment. This phase contains no real release.

For a future release, the server must expose only the requested approved locale and exact version, give each page a canonical URL and `hreflang` links, add descriptive metadata, and remove `noindex` only after publication. Missing locales currently fail publication; there is no unapproved fallback or controlling-language rule. The locale selector uses the site's existing cookie and updates the shell. Print CSS removes navigation and decorative chrome.
