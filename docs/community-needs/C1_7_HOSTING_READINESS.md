# C1.7 hosted application release readiness

The linked Supabase database project is verified. Repository inspection found local Next.js and Fastify workflows, a local validation pipeline, and prior deployment evidence for the database. No authorized hosted Next.js or Fastify provider project, verified owner, deployment destination, or rollback procedure was identified. The connected localhost web and API use hosted Supabase for compatibility checks. No hosted web or API was deployed.

Before an application release, the Founder must identify the approved provider projects, operators, domains, and expected release. The release operator documents separate web/API deploys from a single immutable Git revision and records both running versions, TLS, Auth callbacks and HTTPS redirects, approved CORS and security headers, restricted runtime secrets, CSP, private `no-store` routes, health and monitoring. Run guest and session-bound access smoke checks for current communities, projects and moderation. Confirm public reads and disabled Community Needs routes against actual hosted origins. Test rollback to a compatible previous application release without deleting or reapplying schema history. Preserve immutable logs and coordinate rollback with database and Storage recovery owners.

Keep `AYINOU_COMMUNITY_NEEDS` disabled in release validation. The runtime release is accepted by the pilot only through existing release routing and must exactly match the protected pilot policy and independent attested evidence. A configured value, a build pass and a local compatibility check do not establish release custody. Future department launches must bind each scope to the authorized matching release and independently verified privacy, recovery and support evidence.
