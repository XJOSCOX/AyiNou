# C1 nationwide security and verification

## Scoped testing

The disposable upgrade rehearsal starts from C1.7, seeds an Ouest policy, enrollment and receipt, then upgrades the database and checks the original actor, scope, digest, revision, term and reason. Existing department IDs and all forty department-stage combinations are checked for default closure.

The combined disposable browser and API suite exercises C1.1–C1 final, including the same native lifecycle through project association in all ten department communities. A separate three-department pilot exercise covers independent configuration and quotas, a member enrolled separately in each scope, reviewer-grant isolation, insufficient-coverage denial, scope-specific and nationwide pause, idempotent receipts, retained author reads, denial of ordinary Founder settings access, and independent resumption against current evidence. Live mutations, including activation and attestation fixtures, occur only inside the disposable environment. Release-bound RPCs preserve the same error mappings as their legacy equivalents.

## Issues found during validation

Supabase rejected the planned custom transaction setting. The corrected SQL passes the deployment release explicitly through the private functions. An integration rerun found the normal database denial codes were still mapped only for legacy RPC names. The shared API error mapping now preserves the expected closed, denial and stale-version responses for both versions. The upgrade fixture also uses the native required username metadata.
