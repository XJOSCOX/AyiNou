# C4 disposable recovery verification

The recovery rehearsal derives the isolated E2E database from the runner's guarded disposable project. It takes a PostgreSQL custom-format dump, creates a uniquely named scratch database in the disposable container, restores the dump, and leaves PostgREST attached only to the original database. Before any verification reads, the restored release is explicitly quarantined. The scratch database is removed after the rehearsal.

Both rehearsals passed. The opportunity restore preserved the withdrawn-interest fingerprint, bookmark ownership and the effective publication cutoff. The mentorship restore preserved two exact agreement revisions, learning and session records, and the ended relationship’s safety-restriction marker. The restored release does not enable stage processing. The operational recovery procedure must additionally reconcile recent consent, revocations, session invalidation and safety changes before exposure.

This rehearsal is database-only. Production backup retention, recovery time and recovery point objectives, identity and private Storage restoration, secrets rotation, release attestation and monitored recovery remain separately required.
