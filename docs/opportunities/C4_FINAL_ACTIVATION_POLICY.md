# C4 stage activation policy

A recognized Founder uses the same private workspace and recent-authenticator rules as other protected preparation work. The command names the exact stage and configuration digest and acknowledges the current revision. Activation or pause, its receipt, and all dependent state changes commit in one transaction. A retry with the same request identifier returns its receipt only in the same workspace with an identical command. Operation-specific guards are still enforced.

| Stage | Stage prerequisites | Additional authorization at use |
| --- | --- | --- |
| Opportunity drafts | None | Authorized representative and eligible organization workspace |
| Review and publication | Drafts | Scoped current reviewer staffing to activate; exact assignment acceptance, independence, applicable evidence and approval for each publication |
| External application access | Drafts and publication | Current applicable revision and approved HTTPS destination |
| Native expressions of interest | Drafts and publication | Current eligible publication, applicant consent and authorized recipient |
| Opportunity discovery | Drafts and publication | Current eligible publication with a valid application method, including the existing Event path where applicable |
| Personalized recommendations | Drafts, publication and discovery | Independent member consent and currently eligible result |
| Mentorship intake | None | Current role eligibility, identity checks where required and adult/safeguarding confirmation |
| Mentorship matching and discovery | Mentorship intake | Current role preferences, independent purpose consent, safe privacy and capacity |
| Mentorship requests | Intake and matching/discovery | Current signed selection, eligible participants and recipient consent |
| Relationship coordination | Prepared profile and coordination rules | Creation additionally requires the requests stage, explicit acceptance, and mutual confirmation of the exact agreement. Existing safe relationships do not depend on matching or requests. |

Each stage reports actual preparation revisions and the separate historical-policy requirements for operational approval, privacy, safety and an authorized release. The only release approval that exists in this migration is for the verified disposable runtime. Saving configuration or restoring a prerequisite cannot enable a dependent stage. A future live release needs separate owner authorization.

Pausing drafts leaves existing authorized draft reads available. Publication pause records an indexed cutoff: every earlier listing becomes unavailable and a prior revision cannot be republished. External access and new interest submissions can pause independently. History and consent withdrawal remain subject to current requester and organization permissions. Personalization can pause without disabling Latest or Saved.

Pausing requests invalidates pending outreach and unpublished agreements while preserving established relationships. Pausing coordination stops interaction, preserves safe termination, reporting and authorized history, and places active relationships into their own paused state. Resuming platform coordination does not resume individual relationships. Existing safety restrictions persist after eligibility returns. Emergency pause can be scoped to Opportunities, Mentorship or both.
