# C4.2. Security checks

Disposable coverage includes covered typed schemas, verified and unverified publishers, independent geographically scoped assignments, conflict denial, a separate challenge reviewer, exact publication and destination revisions, organization-scoped expressions of interest, duplicate request receipts, privacy withdrawal, blocked recipients, native Event eligibility, restriction, and invalidation after revoked organization verification.

The API validates commands and derives actor, session and workspace on the server. PostgreSQL checks them again, keeps every new relation private, records mutations atomically, and preserves existing grant boundaries. Closed hosted runtime and absent hosted fixture prevent organization or reviewer actions. Neither settings preparation nor organization verification can activate a feature.

Hosted postflight verifies current history, no other migration, exact SQL and RLS, existing data preservation, and empty operational tables. Browser verification uses existing accounts and no hosted test mutations. See [implementation report](C4_2_IMPLEMENTATION_REPORT.md).
