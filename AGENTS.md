# Ayinou repository instructions

- Inspect the current implementation, effective SQL, tests and Git state before editing. Preserve unrelated tracked and untracked work. Follow nested repository instructions in their directories, including the Next.js guide in [apps/web/AGENTS.md](apps/web/AGENTS.md).
- Reuse established modules, authorization boundaries and shared contracts. Keep existing API consumers, stored data and migration history compatible. Work on main under the repository [workflow](docs/WORKFLOW.md).
- Apply the [engineering standards](docs/standards/ENGINEERING_STANDARDS.md), [security and privacy standards](docs/standards/SECURITY_AND_PRIVACY.md) and [audit event policy](docs/standards/AUDIT_EVENT_POLICY.md). Enforce privileges on the server and in PostgreSQL where applicable. Document actor/scope checks, sensitive data handling, retention, export, deletion and holds. Commit important success events with the mutation.
- For product changes, keep Haitian Creole, French, English and Spanish complete. Check responsive layouts, keyboard navigation, focus, labels, error recovery and accessible feedback.
- Test allowed and denied authorization and relevant concurrency, retries, and lifecycle paths. Update the [audit inventory](docs/standards/AUDIT_COVERAGE_MATRIX.md) and the [feature review register](docs/standards/feature-reviews.json) as coverage changes. Address the [completion checklist](docs/standards/FEATURE_COMPLETION_CHECKLIST.md) in the implementation report.
- Test database writes using disposable infrastructure. Hosted migrations need separate explicit production authorization. Describe and verify the exact target, pending versions, rollout, recovery and postflight checks.
- Verify applicable checks, CI and actual deployment state before reporting completion. A successful compilation alone does not establish feature readiness. Record limitations and follow-up owners using the [maintenance guidance](docs/standards/CONTINUOUS_MAINTENANCE.md).
